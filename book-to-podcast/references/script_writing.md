# 播客脚本写作规范

目标：写出来的字，**念出来像人在说话**，而不是像在朗读文章。
这是整条流水线里最容易翻车的一步——知识点拆得再好，脚本一书面化，成片就废了。

---

## 一、角色设定（双人对话）

| 角色 | 定位 | 该做的 | 不该做的 |
|---|---|---|---|
| **主持人** `host` | 听众代言人 | 提问、追问、打断、说"等一下我没懂"、把抽象拉回具体、总结 | 抢着讲知识、比嘉宾还懂 |
| **嘉宾** `guest` | 领读者 | 讲解、举例、纠正误解、给判断、承认不确定 | 一口气讲 300 字不停、念定义 |

**发言配比 ≈ 主持人 35% / 嘉宾 65%。**
主持人不是捧哏，要真提问。好的主持人问题：

- "这跟我们平时说的 XX 有什么区别？"
- "那反过来说，什么情况下这套就不成立了？"
- "你能举个我们日常能碰到的例子吗？"
- "等等，那不就等于……？"（故意说出听众会有的误解，让嘉宾纠正）

**单人独白**时，用自问自答制造对话感，别一路平铺。

## 二、单集结构

```
[0:00-0:40]  钩子      一个反直觉断言 / 一个具体场景 / 一个尖锐问题
[0:40-1:30]  预告      这集回答什么问题，听完能带走什么
[1:30-  ...]  主体      知识点 1 → 案例 → 知识点 2 → 案例 → …
             每个知识点: 抛出 → 解释 → 举例 → 主持人追问 → 澄清边界
[ -2:00]     转折      反直觉点 / 局限 / 争议（这集的记忆锚点）
[ -1:00]     落地      2-3 条可执行动作
[ -0:30]     收尾      一句话总结 + 下集钩子
```

### 钩子必须具体

反例（空洞）：
> 今天我们来聊聊《反脆弱》这本书，它讲的是如何在不确定性中获益。

正例（具体）：
> 2008 年之前，冰岛的银行系统被评为全球最稳定之一。三年后它整个崩了。
> 而同一时期，纽约街边那些看起来随时会倒闭的小餐馆，活下来一大半。
> 今天想聊的就是这件事——为什么"看起来稳定"，反而是最危险的信号。

**开场禁止**：「欢迎收听本期节目」「大家好我是XX」「今天我们要讲的是」——
这类套话在前 10 秒流失听众。直接进内容，自我介绍放到钩子之后。

## 三、书面语 → 口语

### 硬性替换

| 书面 | 口语 |
|---|---|
| 首先…其次…最后… | 第一件事是…／然后呢…／最关键的是… |
| 综上所述 / 由此可见 | 所以你看 / 说白了 |
| 该理论认为 | 他的意思是说 |
| 具有重要意义 | 这事儿的分量在于 |
| 进行分析 / 做出判断 | 分析 / 判断（去掉"进行""做出"） |
| 在……的情况下 | 要是…… / ……的时候 |
| 不仅……而且…… | 不光……还…… |
| 之所以……是因为…… | 为什么呢？因为…… |

### 句长

- **单句不超过 40 字**（中文）／ 25 词（英文）。超了就拆
- 长定语从句一律拆成两句
- 每 3–4 句插一个短句（5–10 字）调节奏："对。" "问题就在这儿。" "但是。"

改写示例：

> ❌ 作者通过对航空业和银行业的对比分析指出，一个由脆弱个体组成的系统反而可能
>    在整体层面表现出反脆弱特征，因为个体的失败为系统提供了改进所需的信息。
>
> ✅ 他拿航空业和银行业做了个对比。
>    航空业每出一次事故，全行业的规则就收紧一次，整体越来越安全。
>    但对那架飞机上的人来说，这是灭顶之灾。
>    **个体是脆弱的，系统是反脆弱的。**
>    为什么？因为每次失败都给系统送了一条信息。

### 允许并鼓励

口头语让声音像人：`其实`、`你想啊`、`说白了`、`对吧`、`我举个例子`、
`这里有意思的是`、`换句话说`、`但问题来了`。

**别过量** —— 每 100 字最多 1–2 个，否则显得啰嗦。

## 四、TTS 友好规则（不遵守会出可听见的错）

1. **数字**：写成朗读形态
   - `2008年` ✅ ／ `1/3` ❌ → `三分之一` ／ `85%` → `百分之八十五`
   - `第2章` → `第二章` ／ `3.14` → `三点一四`
2. **英文缩写**：首次出现展开
   - `GDP` → `GDP，也就是国内生产总值` ／ `AI` 这类已通用的可直接用
3. **多音字**：中文注意 `了(le/liǎo)` `的(de/dí)` `重(zhòng/chóng)` `行(xíng/háng)`
   `长(cháng/zhǎng)` `分(fēn/fèn)`。歧义处换词，别赌 TTS 读对
4. **符号**：脚本正文里不要出现 `*` `#` `-` `>` ``` ` ``` `[]()` ——
   `tts_render.py` 会清洗，但源头干净更保险
5. **括号注释**：`（笑）`、`（停顿）`、`[BGM渐入]` 会被自动清洗成停顿或删除，
   可以放心用来标注表演提示
6. **省略号**：`……` 会产生自然停顿，用来断意群
7. **书名号**：`《反脆弱》` 多数引擎会正常处理，但连续多个书名号会读得很碎——
   列举书单时改成"第一本，反脆弱；第二本，……"
8. **换行**：一条 `line` 就是一次合成调用。单条控制在 **20–120 字**——
   太短碎、太长则语调平且失败重试代价高

## 五、节奏与停顿

在脚本 JSON 里用 `pause_after`（秒）：

| 场景 | 建议值 |
|---|---|
| 同一人连续说 | 不设（用默认 gap 0.35s） |
| 换人说话 | 不设（合成时自动 1.8×gap） |
| 抛出问题后留白 | `0.8` |
| 重点结论之后 | `1.0` |
| 章节/话题切换 | `1.5` |
| 全集结束前 | `1.2` |

**每 40–60 秒必须有一次角色交替**。连续 90 秒单人输出，听众会走神。

## 六、时长换算

| 语言 | 语速（默认） | 18 分钟约需 |
|---|---|---|
| 中文 | 250–280 字/分 | 4500–5000 字 |
| 英文 | 150–170 词/分 | 2700–3000 词 |
| 日文 | 350–400 字/分 | 6300–7200 字 |
| 韩文 | 300–340 字/分 | 5400–6100 字 |
| 西/法/德 | 140–160 词/分 | 2500–2900 词 |

写完先数字数再渲染。**用 `--dry-run` 可直接看总字符数与预估费用。**

## 七、脚本 JSON 格式

完整 schema 见 `assets/script_schema.json`，最小可用示例：

```json
{
  "episode_id": "ep01",
  "title": "为什么'稳定'是最危险的假象",
  "language": "zh",
  "engine": "edge",
  "default_gap": 0.35,
  "voices": {
    "host":  {"edge": "zh-CN-YunxiNeural",    "aliyun": "Ethan", "rate": "+6%"},
    "guest": {"edge": "zh-CN-XiaoxiaoNeural", "aliyun": "Cherry"}
  },
  "lines": [
    {"speaker": "host", "text": "2008年之前，冰岛的银行系统被评为全球最稳定之一。三年后，它整个崩了。", "pause_after": 0.8},
    {"speaker": "guest", "text": "对，而且同一时期，纽约街边那些看起来随时要倒闭的小馆子，活下来一大半。", "chapter": "开场"},
    {"speaker": "host", "text": "这就有意思了。稳定的死了，脆弱的活了？"}
  ]
}
```

要点：

- `voices` 里每个 speaker 可为每个引擎各配一个音色，切引擎时脚本不用改
- `rate` / `pitch` / `volume` 是 edge 引擎参数；云端引擎用 `speed_ratio` / `speed`
- `chapter` 字段会生成 MP3 章节标记（需 ffmpeg）
- 顶层 `engine` 可被命令行 `--engine` 覆盖

## 八、自检清单

渲染前逐条过：

- [ ] 开场 30 秒内出现了具体的人、事、数字或场景
- [ ] 没有「欢迎收听」「大家好」类套话开场
- [ ] 最长的一句话没超过 40 字（中文）
- [ ] 每个知识点都配了至少一个具体例子
- [ ] 主持人至少问了 5 个真问题（不是"是吗""然后呢"）
- [ ] 出现了至少一处「反直觉」或「作者可能错在哪」
- [ ] 结尾给了可执行动作，不是"希望对你有启发"
- [ ] 全文没有 Markdown 符号、没有阿拉伯数字分数百分数
- [ ] 字数对得上目标时长（见第六节）
- [ ] 单条 line 都在 20–120 字之间
